# 项目计划（初稿）

课程：数字信号处理 · 电子系统设计实训  
题目：IC卡门禁系统设计

## 目标

实现课设级 IC 卡门禁闭环：读卡 → 协议解析 → 数字鉴权 → 控制输出。

## 验收分级

1. **基础**：读卡号、白名单开门、错误卡报警  
2. **提高**：管理员增删卡、进出记录  
3. **可选**：掉电保存、重读滤波/防冲突说明  

## 里程碑（建议 4–6 周）

| 阶段 | 时间 | 产出 |
|------|------|------|
| 需求与方案 | 第 1 周 | 功能清单、框图、器件清单 |
| 环境与骨架 | 第 1 周末 | Win/Mac 均可编译的 PlatformIO 工程 |
| 硬件联调 | 第 2 周 | 打印卡号 UID |
| 核心逻辑 | 第 3 周 | 白名单鉴权 + 开关门 |
| 管理与记录 | 第 4 周 | 增删卡、简单日志 |
| 整理交付 | 第 5–6 周 | 报告、演示、答辩材料 |

## 双系统策略

- 工具：VS Code + PlatformIO（同一套工程）
- 同步：Git + GitHub Private
- Mac：写码、文档、编译验证
- Windows：烧录联调、与机房/验收环境对齐
- 硬门槛：以验收系统（很可能 Windows）编译 + 烧录通过为准

## 风险

| 风险 | 对策 |
|------|------|
| 读卡不稳定 | 先做只打印 UID 的最小 demo |
| 范围过大 | 不做联网/人脸/云端 |
| 双系统漂移 | 每周至少两边各编译一次；优先跨平台工具链 |
| 报告滞后 | 第 2 周起记录实验现象 |
